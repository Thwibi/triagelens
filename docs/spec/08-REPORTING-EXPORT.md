# 08 — Reporting and Export

## 1. Report content (HTML, Markdown, PDF, JSON share one data model)

Sections, in order (each toggleable except 1 and 9):

1. **Cover / case summary** — title, case name, analyst, generated-at (UTC + case TZ), tool version, ATT&CK version, ruleset hash, detection profile.
2. **Executive summary** — auto-generated factual paragraph from data (no free-form AI text): time span, sources and event counts, number of alerts by level, top 3 techniques, top 5 external IOCs, affected hosts/users. Template-driven with deterministic wording.
3. **Alert overview** — table of included alerts (by selected statuses) sorted by score: level, title, technique(s), host, user, window, count, status.
4. **Alert details** — per alert: description, ATT&CK tactic/technique list with names and URLs, rule id/title/level, false-positive notes, score breakdown, analyst notes, up to N evidence events (time, host, key fields; raw optional), IOCs from evidence.
5. **MITRE coverage** — matrix rendering (HTML/PDF: static SVG heat grid; MD: list by tactic) + Navigator layer file attached.
6. **IOC table** — external, non-allowlisted IOCs grouped by type, defanged by default, with confidence, first/last seen, linked alerts, analyst state.
7. **Timeline** — SVG chart of event volume with alert markers and a chronological key-events list (first/last alert, first/last malicious-IOC occurrence).
8. **Entities** — hosts and users with counts.
9. **Evidence integrity and methodology** — table of sources (filename, size, SHA-256, log type, parse errors), detection run details, list of rules run/skipped/errored counts, note that logs were processed locally, audit-log chain verification result.
10. **Appendix** (optional) — raw events for included alerts.

JSON report schema: `{meta:{...}, summary:{...}, alerts:[AlertDetail...], iocs:[IOC...], mitre:{...}, timeline:{...}, entities:{...}, sources:[...], integrity:{...}}` with a `schema_version` field (start at `"1.0"`).

## 2. Rendering

- **HTML**: Jinja2 with `autoescape=True` (all log-derived text escaped), single self-contained file (inline CSS, inline SVG, no external requests, no JS). Print stylesheet included (page-break rules, hide nav).
- **PDF**: generated from the HTML via WeasyPrint when installed; if absent the endpoint returns `422 PDF_UNAVAILABLE` with instructions, and the UI hides the PDF option (health endpoint reports `pdf_available`).
- **Markdown**: GitHub-flavoured; code fences for commands/raw lines (fence length chosen dynamically to exceed any backtick run in the content); tables escaped (`|` → `\|`).
- Reports are written to `data/reports/<case_id>/<report_id>.<ext>`, hashed (SHA-256) and recorded in `reports` and the audit log.
- Long cells are truncated with an ellipsis marker only in tables; the full text is in the alert details/appendix.

## 3. ATT&CK Navigator layer

`GET /api/cases/{id}/mitre/navigator-layer` returns a layer file importable by ATT&CK Navigator:

```json
{
  "name": "TriageLens - <case name>",
  "versions": {"attack": "<attack_version major>", "navigator": "5.1.0", "layer": "4.5"},
  "domain": "enterprise-attack",
  "description": "Generated by TriageLens <version> on <UTC timestamp>. Ruleset <hash>.",
  "filters": {"platforms": ["Windows", "Linux", "macOS", "PRE", "Containers", "Network", "IaaS", "SaaS", "Office 365", "Azure AD", "Google Workspace"]},
  "sorting": 3,
  "layout": {"layout": "side", "aggregateFunction": "max", "showID": true, "showName": true, "showAggregateScores": false, "countUnscored": false},
  "hideDisabled": false,
  "techniques": [
    {"techniqueID": "T1110.001", "tactic": "credential-access", "score": 3, "color": "", "comment": "2 alerts; max level high; rules: SSH Brute Force From Single Source", "enabled": true, "metadata": [], "links": [], "showSubtechniques": true}
  ],
  "gradient": {"colors": ["#ffe766", "#ff6666"], "minValue": 0, "maxValue": 4},
  "legendItems": [],
  "metadata": [],
  "links": [],
  "showTacticRowBackground": false,
  "tacticRowBackground": "#dddddd",
  "selectTechniquesAcrossTactics": true,
  "selectSubtechniquesWithParent": false
}
```
`score` = max severity ordinal among linked alerts (informational 0.5→1, low 1, medium 2, high 3, critical 4; use integers: informational=1, low=1, medium=2, high=3, critical=4); `comment` summarizes alert count and rule titles (≤ 500 chars). One entry per (technique, tactic) the alert mapped to. Sub-technique alerts also emit the parent entry with `comment` prefixed `via sub-technique`.

## 4. CSV/JSONL exports

- Alerts CSV: `alert_id,level,score,status,rule_id,rule_title,tactics,techniques,host,user,first_seen,last_seen,match_count,analyst_notes` (CSV-injection safe: values starting with `= + - @ \t \r` are prefixed with `'`).
- Events CSV/JSONL: current filter result, all normalized columns (+ `fields_json` as a JSON string in CSV), streamed.
- IOC exports: see 05 §8.

## 5. Acceptance

- HTML report opens offline with zero network requests (checked by test parsing the HTML for external URLs in `src`/`href`/`url()` other than visible reference text).
- Report generated twice from the same data differs only in the generation timestamp and report id.
- Navigator layer validates against the Navigator layer JSON schema (vendored in tests).
- CSV outputs pass a formula-injection test and round-trip through Python's `csv` module.
